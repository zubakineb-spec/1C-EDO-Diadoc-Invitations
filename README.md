# Рассылка роуминговых приглашений 1С-ЭДО по действующим контрагентам Контур.Диадок — v0.1.21

Целевая конфигурация: **1С:Бухгалтерия ПРОФ 3.0.202.14**. Интеграция проверяется с **Контур.Диадок 4.68.0**.

## Цель

Начать обмен через 1С-ЭДО только с теми контрагентами, с которыми у организации уже есть действующий обмен в Контур.Диадок.

## Текущая логика

- источник кандидатов — только партнеры Диадок `IsMyCounteragent`;
- авторизация выполняется через уже подключенный Контур.Диадок, без выбора файла EPF;
- сопоставление выполняется по ИНН/КПП с блокировкой неоднозначных случаев;
- список сортируется по наименованию контрагента;
- статус `требуется роуминговое приглашение` присваивается только безопасным кандидатам;
- массовая роуминговая пачка допускает только `FnsParticipantId` с префиксом **`2BM`**;
- `2AE`, `2AL` и любые другие операторские идентификаторы исключаются;
- перед передачей в типовой помощник 1С-ЭДО выполняется повторная проверка состояния и префикса `2BM`;
- уже настроенный обмен и уже отправленное приглашение повторно не отправляются;
- кнопка отправки: **«Отправить роуминговое приглашение»**.

## Важный runtime-gate

Получение активных партнеров Диадок 4.68.0 подтверждено в runtime начиная с v0.1.15. Для массовой отправки v0.1.21 остается контрольной версией: перед массовым запуском нужно проверить на одном контрагенте, что типовой помощник 1С-ЭДО не подменяет переданный `2BM...` на ранее сохраненную учетную запись другого оператора (например `2AE...`).
